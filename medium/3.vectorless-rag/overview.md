## 개요

이 저장소는 **Vectorless RAG**(Retrieval-Augmented Generation)를 시연합니다. 이는
전통적인 벡터 데이터베이스를 **지능형 트리 기반 문서 구조**와 **LLM 추론**으로
대체하는, 문서 질의응답에 대한 새로운 접근 방식입니다.

기존 RAG 시스템이 사용하는 방식:
- ❌ 벡터 임베딩 (높은 비용, 느림, 의미 표류(semantic drift))
- ❌ 고정 크기 청크 (맥락 손실, 인위적인 경계)
- ❌ 유사도 검색 (관련성 ≠ 유사도)

이 시스템이 사용하는 방식:
- ✅ **계층적 문서 트리** (목차와 유사)
- ✅ **LLM 추론** (매칭이 아닌 이해)
- ✅ **맥락 인식** (문서 구조 유지)
- ✅ **완전한 인용** (페이지 번호로 추적 가능한 결과)

## 🏗️ 시스템 아키텍처

이 시스템은 **그래프 기반 에이전트**(LangGraph)를 사용하여 네 가지 주요 단계를
거쳐 문서 트리를 지능적으로 탐색합니다:

1. **Analyze 노드**: LLM이 현재 섹션의 관련성을 평가하고 탐색 전략을 결정합니다.
2. **라우팅 결정**: 신뢰도 점수에 따라 자식으로 하강하거나, 콘텐츠를 검색하거나,
   되돌아갑니다(backtrack).
3. **콘텐츠 검색**: 관련 문서 섹션에서 전체 텍스트를 추출합니다.
4. **답변 생성**: LLM이 출처와 인용을 포함한 최종 답변을 종합합니다.

**워크플로 시각화 PNG**가 자동으로 생성되어 `results/workflow.png`에 저장되며,
전체 에이전트 상태 그래프 구조를 보여줍니다.

문서 트리 자체는 **5단계 파이프라인**으로 구축되며, 문서 구조 탐지를 점진적으로
정교화합니다. LLM 호출 없이 시작하여 복잡한 계층 구조가 필요한 경우에만 AI를
사용합니다.

## 📊 핵심 개념

### TreeNode 구조

**TreeNode**는 전체 문서 구조를 보존하는 문서 섹션의 계층적 표현입니다. 각 노드는
다음을 포함합니다:

- **id**: 검색 경로 추적을 위한 고유 식별자
- **title**: 문서의 섹션 제목
- **summary**: 관련성 평가를 위한 AI 생성 요약
- **page_start/page_end**: 인용을 위한 페이지 범위
- **content**: 섹션의 전체 텍스트
- **children**: 중첩된 TreeNode 리스트 (문서 구조 보존)
- **level**: 계층 깊이 (0=루트, 1=섹션, 2=하위 섹션 등)

### 에이전트 기반 검색

**LangGraph 기반 에이전트**는 다음을 추적하는 어노테이션 타입 딕셔너리
(RetrievalState)를 사용하여 문서 트리를 탐색합니다:

- 현재 질의와 탐색 위치
- 전체 문서 트리와 순회 경로
- 검색된 콘텐츠 블록과 추론 내용
- 관련성 판단을 위한 신뢰도 점수 (0.0~1.0)
- 생성된 최종 답변

에이전트는 지능적인 라우팅 결정을 내립니다:
- **Analyze**: 질의에 대한 섹션의 관련성 평가
- **Decide**: 자식 섹션으로 라우팅(descend), 콘텐츠 추출(retrieve), 또는
  되돌아가기(backtrack)
- **Retrieve**: 선택된 섹션에서 전체 텍스트 추출
- **Generate**: 검색된 모든 콘텐츠로부터 최종 답변 종합

### 계층 구조가 검색을 개선하는 방법

자연스러운 문서 구조는 임베딩 없이도 지능적인 탐색을 가능하게 합니다:

- **보존**: 자연스러운 섹션이 여러 문장에 걸친 맥락을 유지
- **탐색**: 계층 구조를 통해 키워드 매칭 대신 주제별 드릴다운 가능
- **추론**: LLM이 문서 구성을 이해
- **인용**: 모든 답변이 특정 페이지와 섹션으로 추적됨

## 🛠️ API 레퍼런스

### 문서 트리 구축

`tree.py`의 `parse_pdf()` 함수는 자동 구조 탐지로 DocumentTree를 생성합니다:

- 테스트를 위한 선택적 페이지 제한 지원
- 트리는 문서 메타데이터(이름, 전체 페이지 수)와 계층적 루트 노드를 포함
- 캐싱은 JSON 직렬화를 통해 별도로 처리됨

### 답변 검색

`retriever.py`의 `retrieve()` 함수는 에이전트 기반 검색 파이프라인을 실행합니다:

- 답변, 순회 경로, 추론 내용, 신뢰도 점수, 출처가 담긴 결과 딕셔너리 반환
- 문서 섹션 전반에 걸친 멀티홉(multi-hop) 추론 처리
- 검색된 모든 콘텐츠에 대한 인용과 페이지 범위 제공

### 워크플로 시각화 생성

`retriever.py`의 `generate_workflow_png()` 함수는 PNG 시각화를 생성합니다:

- 전체 LangGraph 상태 머신을 시각화
- 모든 노드와 조건부 라우팅 로직을 표시
- 지정된 출력 경로에 저장 (기본값: "workflow.png")
- `main.py`에 의해 자동 호출되어 `results/workflow.png`에 저장됨

### 트리 캐싱

DocumentTree 객체는 JSON으로 직렬화하여 재사용을 위해 캐시할 수 있습니다:

- 캐시가 있으면 로드하여 비용이 큰 트리 구축을 건너뜀
- 최초 구축 후 `model_dump()` 메서드로 트리 저장
- 동일한 문서에 대한 반복 질의 속도를 크게 향상

## 🔄 전체 에이전트 동작 과정

### 예시 질문: "Bigtable이란 무엇이며 어떤 문제를 해결하는가?"

**초기 상태:**
에이전트는 현재 위치가 설정되지 않은 상태로 문서 루트에서 시작합니다.

**1단계: Analyze 노드 (루트에서)**
에이전트는 루트 노드의 관련성을 평가하고, 자식 섹션(예: Introduction,
Architecture 등)으로 하강할지 아니면 즉시 콘텐츠를 검색할지 결정합니다.

**2단계: 라우팅 결정**
신뢰도 점수(임계값: 0.3)에 따라 에이전트는 관련 자식 섹션으로 더 깊이 하강하거나
콘텐츠 검색으로 이동합니다.

**3단계: 탐색**
에이전트는 문서 계층 구조를 순회하며 각 섹션의 관련성을 분석하여 높은 신뢰도의
콘텐츠를 찾을 때까지 진행합니다.

**4단계: 콘텐츠 검색**
관련 섹션을 찾으면 에이전트는 해당 노드의 전체 텍스트 콘텐츠를 추출합니다.

**5단계: 답변 생성**
최종 LLM 호출이 검색된 콘텐츠를 종합하여 인용과 출처 추적을 포함한 포괄적인
답변을 만듭니다.

## 📈 Vector RAG 대비 주요 이점

| 측면 | Vector RAG | Vectorless RAG |
|--------|-----------|----------------|
| **청킹** | 고정 512토큰 청크 (맥락 손실) | 자연스러운 섹션 (구조 보존) |
| **임베딩** | 모든 청크를 임베딩해야 함 (고비용) | 없음 (트리 구조만 사용) |
| **검색 품질** | 유사도 매칭 (관련성 놓칠 수 있음) | LLM 추론 (맥락 이해) |
| **인용** | 모호한 청크 ID | 페이지 범위와 섹션 제목 |
| **멀티홉** | 재랭킹 없이는 자주 실패 | 여러 섹션에 걸친 개념을 자연스럽게 처리 |
| **환각(Hallucination)** | 높음 (청크의 의미 표류) | 낮음 (전체 섹션에 근거) |
| **비용** | 지속적인 임베딩 비용 | 일회성 트리 구축 |

## 📚 아키텍처 심층 분석

### 트리 구축 파이프라인

문서 트리는 문서 구조를 점진적으로 정교화하는 **5단계 파이프라인**으로
구축됩니다:

1. **PyMuPDF 내장 TOC** — PDF의 기본 북마크 구조를 읽음 (LLM 호출 0회)
2. **정규식 헤딩 스캔** — "2.3 Column Families"와 같은 번호가 매겨진 헤딩 탐색
   (LLM 호출 0회)
3. **폰트 기반 스캔** — 폰트 메트릭을 분석하여 헤딩 폰트 식별 (LLM 호출 0회)
4. **LLM 구조 탐지** — 정규식이 섹션을 거의 찾지 못할 때 사용, 텍스트 흐름 분석
   (LLM 호출 1회)
5. **섹션별 요약** — 각 섹션에 대해 2문장 요약 생성 (N개의 작은 호출)

여러 탐지 방법은 정규식 결과의 신뢰도를 기반으로 지능적으로 병합됩니다.

### 에이전트 기반 검색 (LangGraph)

검색 에이전트는 다음 구조의 **StateGraph**를 사용합니다:

**상태 변수:**
- `query`: 사용자 질문
- `current_node`: 트리 내 현재 위치
- `tree`: 전체 문서 계층 구조
- `path_taken`: 방문한 노드 ID
- `retrieved_content`: 누적된 콘텐츠 블록
- `reasoning`: LLM 설명
- `confidence`: 관련성 점수 (0.0~1.0)
- `should_descend`: 탐색 결정
- `final_answer`: 생성된 응답

**그래프 노드:**
- analyze: 현재 노드의 관련성 평가
- descend: 자식 노드로 이동
- retrieve: 노드 콘텐츠 추출
- generate: 최종 답변 종합

**조건부 라우팅:**
- 신뢰도 > 0.3 이고 자식이 존재하면 → descend
- 신뢰도 ≤ 0.3 이거나 자식이 없으면 → retrieve
- 최대 깊이에 도달하면 → backtrack(되돌아가기)
